# 架构设计（v0.6：根因分析 + 自我进化 RSI v2 + Harness 层：快慢双脑 · 双层递归 · RRSI · 可靠度模型）

## 1. 总体思路

Kaizen 是一个**神经-符号复合 AI 系统**。根因排序由统计证据和可进化记忆给出，过程确定、可审计；大模型只负责理解、解释和写作，并且可以降级。
在此之上，Kaizen 参照 RSIAgent 加了一条**不依赖真实案例的自我改进通道**：三个 agent 在数字孪生里自主练习，把验证过的经验沉淀进记忆。

**RSI 自我改进和持续学习是同一个功能**：目标都是把“验证过的结论”写进同一套记忆，区别只在标签从哪里来。产线上的标签来自工程师确认根因和 CAPA 验证（权重 1.0，随时发生）；RSI 的标签来自数字孪生里验证 agent 的判定（权重 0.5，按需或每晚）。界面上两者合并成一个“自我进化”页面，分“RSI 学习”和“持续学习”两页。

| 层 | 负责什么 | 技术 | 依赖大模型？ |
|---|---|---|---|
| 统计因果内核 | 共性分析、晶圆图空间特征、FDC 偏移、变点/PM 时序 | 纯 Python | 否 |
| 可进化记忆 | 根因先验（症状→根因份额）、机台热点、**证据权重**（v0.4）、流程与教训（带条件与通过/失败次数） | Dirichlet 共轭 + 条件 logit + 记忆条目 | 否 |
| 自我进化（RSI v2） | 数字孪生中的自主探索：课程按信息价值出题、执行作答、验证判定；证据权重重拟合必须过验收门 | 孪生 + 三角色 + BRS / CAL / DRS + 验收门 | 否（课程可用 LLM） |
| LLM 层 | 5W2H、5-Why、措施细化、评审、追问 | Pydantic AI 2.71（调用框架，不是模型） | 是（可降级） |
| 代码模式调查员 | 写 Python 在沙箱里核查假设 | pydantic-ai-harness CodeMode + Monty | 是（可跳过） |
| 编排 | 分析流程、RSI 会话、夜间任务 | DBOS 3.6 持久化工作流（SQLite，进程内） | 否 |
| 显示 | 主区域默认是对话；案例、CAPA、自我进化等功能放在左侧栏，点开后在同一主区域完整显示；关案走人工批准 | AG-UI 1.0（ACTIVITY / STATE / 中断，零构建前端） | 否 |
| 可选接入 | Claude / VS Code / Cursor 等 MCP 客户端 | MCP 2026-07-28 + MCP Apps（可关闭） | 否 |

```text
浏览器 ── Nginx ── Kaizen（FastAPI 单进程）
                    ├─ /           控制台：左侧栏（新对话 · 功能 · 最近对话）+ 主区域（默认对话，点开功能后完整显示）
                    ├─ /agui       AG-UI 1.0：思考过程 + 回答、面板卡片（ACTIVITY_*）、关案中断与恢复、自我进化直播
                    ├─ /api        REST
                    ├─ /mcp        可选：MCP 客户端调用工具
                    ├─ DBOS 工作流：rca_workflow（分析）· rsi_workflow（自我改进）· benchmark_workflow · nightly_learning
                    └─ SQLite（WAL）/ PostgreSQL：案例、原始数据、分析、CAPA、可进化记忆、证据权重版本、RSI 会话与练习题、审计
```

**DBOS 和 agent 的关系**：agent 决定每一步做什么（分析、排序、写报告、出题、判定）。DBOS 把每一步的输出检查点到数据库，崩溃后从最后完成的那一步继续。DBOS 是 agent 的运行底座，不是 agent 本身。

## 2. RSI 递归自我改进（对应 RSIAgent，arXiv:2609.15364）

### 2.1 三个角色，三种权力互相制衡

| 角色 | 独占的权力 | 在 Kaizen 中怎么做 |
|---|---|---|
| 课程 agent | 决定练什么 | 按**信息价值**选题（v0.4）：知识梯度 KG(\*) × 证据模糊率，即“再练几道这类题，留出集期望命中率能涨多少”；广度阶段按工段轮转保证覆盖；校准阶段按信息价值分配症状、难度易:中:难 = 2:4:4；深度阶段按“失败驱动 / 压力测试（证据更弱、加无关机台 PM 干扰）”加难；连续 8 题没有带来新知识或达到 36 题上限即停止。可选用与执行 agent 不同的大模型 |
| 执行 agent | 写记忆 | 用当前记忆（先验 + 热点 + 证据权重）对练习题做根因分析并提出整改；首个假设被验证否定时换下一个（动作—验证循环，最多 3 次，校准题最多 5 次以减少选择偏差）；**只在验证判定之后**合并经验，验证过的结论同时成为证据权重的训练样本 |
| 验证 agent | 判真假 | 只接收验收要求和环境反馈：按提议整改后，孪生里同一时段的指标与整改前、基线的对比。看不到执行 agent 的排序、理由和记忆。恢复比例 ≥ 60% 且措施齐全才通过；改善低于量测噪声一律不通过 |

论文的失败分析指出，**验证不完整**和**记忆固化不可靠**会互相放大：一个被接受的错误会变成规则，一路传播下去。Kaizen 的对应设计有三点：
- 验证 agent 刻意保持为基于数值环境反馈的确定性判定，而且宁严勿松；
- 每条记忆都保留“在什么证据条件下”和通过/失败次数，而不是只存结论；
- 失败多于成功 2 次以上的记忆自动停用，人工也可以随时停用。

### 2.2 数字孪生（RSI 的“环境”）

孪生里藏着本厂的两张表，三个 agent 都看不到：
- 各症状下根因的真实频率，与教科书先验不同；
- 根因的多发机台。

课程 agent 只能指定“症状 + 难度 + 是否加干扰”，孪生按真实规律抽取根因，生成 MES 批次履历、晶圆图、FDC、PM 事件。验证时孪生只返回干预后的指标，从不直接给答案。真因只记在练习题的审计字段里，供事后检查验证 agent 判得对不对。

孪生里有 5 类症状（底填空洞、老化早期失效、SLT 失效、液冷泄漏、套刻漂移）在产线历史上没有或很少案例，这正是 RSI 能先把记忆建起来的地方。

### 2.3 三阶段探索（v0.4：广度 → 证据校准 → 深度）

```text
s_eval（不做 RSI 的基线）
 → 广度 BRS：课程出 12 题（每个症状 1 题）→ 每波最多 4 题并行 → 合并记忆 → 重拟合证据权重（过验收门）→ 评估
 → 证据校准 CAL：480 道低成本练习，每波 24 题并行；每波后重拟合证据权重（过验收门）
       冷启动（没有产线历史）：校准题同时更新先验与热点
       在线（已有产线记忆）：校准题只学证据权重，不改动产线先验（“证据长什么样”可以迁移，“各根因多常见”以产线为准）
 → 深度 DRS：串行；每题验证后立即固化记忆；按信息价值 / 失败驱动出题；每 4 题重拟合一次；课程决定何时停
 → s_finish
```

每个步骤都是 DBOS 检查点，崩溃后从断点继续，不会重复练习或重复写入记忆。进度经 DBOS Stream 推给控制台，AG-UI 事件映射如下：
- BRS / CAL / DRS → STEP_STARTED / STEP_FINISHED
- 每题的三角色 → SUBAGENT_STARTED / SUBAGENT_FINISHED；校准题按波次汇总为 CUSTOM `rsi.cal`
- 证据权重重拟合与验收门结果 → CUSTOM `rsi.weights`
- 学习曲线 → STATE_DELTA（JSON Patch）；对话里的进度卡片 → ACTIVITY_DELTA

### 2.4 证据权重与验收门（v0.4 的核心改进）

排序原来是专家设定的因子乘积：后验 ∝ 先验 × 共性分析因子 × FDC 因子 × PM 因子 × 热点因子。v0.4 给每类证据一个可学习的指数：

```text
log P(根因 c | 证据) = Σ_k w_k · log 因子_k(c) − log Z        （条件 logit / 带权重的专家乘积）
```

- w 在所有症状间共享，只有 5 个参数，一道验证过的练习题就能同时改进所有症状的判断；
- 以专家设定 w = 1 为中心加高斯先验（岭回归），牛顿法求最大后验；样本不足 20 个时保持现状；
- 训练标签只来自**已验证**的结论：孪生里验证 agent 判定 PASS 的整改对象（最近 1500 道）+ 产线上工程师确认的根因；
- **验收门**（RSIAgent 这一层的门）：每次重拟合得到的候选权重，都要在封存的验收门面板上和在用权重做配对比较，全部满足才采纳并保存为新版本（`evidencemodel` 表）。依据是 OpsHarness（arXiv 2608.25661）：去掉验收门的自我进化版本比不进化还差。v0.7 把它改严了：
  - 面板从 120 题扩到 240 题（每症状 20 题，分层），v0.6 只比点估计，基本是在比噪声；
  - 配对 bootstrap：对数损失（候选 − 在用）95% 区间上界 ≤ +0.01 且平均差 ≤ 0；首位命中率配对区间下界 ≥ −2 个百分点；
  - 分组护栏：任何一个症状的面板对数损失变差不超过 0.15，防止某个症状被学坏、又被其它症状的改善平均掉；
  - 面板轮换：每采纳一次更新就换一块全新的面板（孪生可以无限出题），防止同一块面板被反复用来做决定后，权重被“调”向面板本身（可复用留出集问题，Dwork et al. 2015）。
- 学到的权重（冷启动 v2，代表性种子）：先验 ×0.9–1.15、**共性分析 ×3–5**、FDC ×1.2–1.9、PM ×1.0–1.2、热点 ×1.0–1.4。也就是说，专家设定低估了共性分析证据的说服力：先验一旦学得有把握，强证据反而压不过它。这正是 v0.3 的瓶颈（见 2.6）。
- 证据权重同样来自两条来源：产线关案后会重拟合（`source=production`），夜间任务也会重拟合（`source=nightly`）。

### 2.5 测试时复用

分析真实案例时记忆是**冻结**的，只读不写（使用最新一版通过验收门的证据权重）。真实案例的学习只发生在工程师确认根因或 CAPA 验证之后，这和论文“探索结束后冻结记忆、测试时课程 agent 与记忆更新全部停用”一致。在控制台里，关案还要经过 AG-UI 中断的人工批准（见第 5 节）。

### 2.5.1 产线变更与部分遗忘（v0.5）

产线不是一成不变的。`rsi/twin.py` 的 `CHANGES` 记录了过去一年 11 次产线变更（换供应商、新机台导入、PM 程序调整…），
每次变更改变一个症状的根因分布；孪生按“时段”同步这些变更，留出测试集和验收门面板也按时段生成。

- 变更生效时，受影响症状学到的份额只保留 20%（`FORGET_KEEP`），向教科书先验收缩，让变更后的新证据更快生效；
  真实案例预序回放用同样的规则。
- 下一次 RSI 会话把这些症状作为重点：课程 agent 的校准题比例提高到 4 倍，这部分校准题也更新先验（权重仍为 0.5）。
- 会话结果持平时写明原因：没有新的产线变更（`no_change`），或变更本身没有让命中率下降（`no_gap`）。

演示数据按时间回放（`app/seed.py`）：建案时用当时的记忆分析，关案时学习，每月一次改进周期与证据权重重拟合，
每次产线变更两天后一次 RSI 会话。12 次会话中 11 次提升了留出集首位命中率，1 次持平。

### 2.6 怎么证明它有用：留出测试集、消融与天花板

- **留出测试集**：每个症状 40 题，共 480 题（v0.3 为 240 题；p≈0.6 时标准误从约 3.2 降到约 2.2 个百分点）。根因按本厂真实分布配比，中等/困难各半，种子与练习、验收门都不重叠。指标：首位命中率（binary）与真因后验（partial）。
- **参考天花板**：知道孪生真实先验、且证据权重直接在测试集上拟合时能达到的命中率（74.6）。任何学习都不可能稳定超过它，所以用“缩小了多少可提升空间”衡量进步。
- **冷启动消融**（新产线，从教科书知识出发；**10 个随机种子**，报告均值与最差值）：

| 模式 | 首位命中率（均值 / 最差） | 真因后验 | 练习题数 |
|---|---|---|---|
| 不做 RSI | 56.0 / 56.0 | 39.5 | 0 |
| 仅广度 BRS | 54.7 / 48.1 | 41.1 | 12 |
| 仅深度 DRS | 52.9 / 45.6 | 43.8 | 36 |
| 论文方案 BRS→DRS（v0.3） | 57.6 / 52.1 | 43.4 | 48 |
| ＋ 证据权重学习 | 62.2 / 59.0 | 46.6 | 48 |
| **＋ 证据校准（v2，默认）** | **73.5 / 72.3** | **58.9** | 528 |
| 参考天花板 | 74.6 | — | — |

  v2 缩小了 94% 的可提升空间（(73.5 − 56.0) / (74.6 − 56.0)），10 个种子里最差的一次（72.3）也好过 v0.3 最好的一次。

- **各项改进分别贡献多少**（同一套 10 个种子，部分实验在 240 题测试集、校准 120 题时完成）：
  - 证据权重：同样 48 道题，57.6 → 62.2；
  - 校准题数量：120 / 240 / 480 题 → 67.8 / 69.1 / 71.0（240 题测试集）；
  - 半天花板分解（校准 120 题时）：真实先验 + 学到的权重 71.8，学到的先验 + 最优权重 69.0。先验和权重都还有余量，所以两者都要学；
  - 课程：信息价值课程 vs 旧的缺口分 vs 随机，在标注少时差别明显（“＋证据权重”档 59.9 / 56.5 / 57.0），在 v2 里约多 1 个点（67.8 / 67.5 / 66.8）；
  - 验收门：在干净的孪生里不改变均值（73.5 vs 不设门 73.5），拒绝了 36% 的重拟合（与 OpsHarness 报告的 37% 接近）；它的作用在标签有偏或有噪声时才体现：在线会话的深度阶段，难题由课程挑选、带选择偏差，验收门拦下了 10 次会让面板退步的重拟合；单元测试里把标签随机打乱，重拟合会被拒绝。

### 2.7 为什么 v0.3 的 RSI 效果不好（诊断记录）

- v0.3 的报告是 4 个种子、240 题测试集上“55.0 → 61.1”。换成 10 个种子、480 题之后，论文方案只有 **56.0 → 57.6**，在噪声范围内。之前的数字是运气好的种子。
- RSIAgent 论文自己的提升也不大：OSWorld-v2 binary 37.8 → 42.7，Agents' Last Exam 49.3 → 50.8，分阶段消融只有 4 个任务。所以“效果不太好”不是复现错误，而是这个方法本身的上限：它只积累经验文本 / 计数，而不改进判断本身。
- 瓶颈定位：把 240 题分成“强证据”和“弱证据”两组，v0.3 学到的先验让弱证据题从 35.9 提到 56.9，却让强证据题从 88.5 **掉到** 78.2：手工设定的证据因子偏保守，先验一学得有把握，强证据就压不过它了。所以必须同时学“每类证据该信多少”。
- 这也和文献的主流结论一致：冻结权重的自我改进，大的提升来自“让经验去更新模型本身 + 大量可验证的练习 + 验收门”，而不是更多的经验笔记（详见 [04 调研](04-芯片制造产线与前沿技术调研.md) 第 9 节）。

- **诚实的边界**：
  - 全部是模拟数据；孪生没有用本厂数据校准时，学到的是孪生而不是产线。所以在线模式下校准题不改动产线先验，孪生经验权重也只有 0.5；
  - 在线会话（演示库，已有产线记忆）：首位命中率 64.8 → 广度后 67.7 → 校准后 69.0 → 深度阶段在 66.9–73.5 之间波动，最后停在 73.5。深度阶段每题都会推动先验，单次结束点有运气成分；
  - 校准 480 题在本孪生里只要几秒；真实孪生仿真更贵时，需要按信息价值缩减题量。

### 2.8 快脑小模型与 Harness 层（v0.7）

RSI 与持续学习改进的是“记住了什么”；快脑小模型是一个真正训练出来、拥有裁决权的排序模型；Harness 层管“这一案怎么答”。逐条文献依据见 [05-RSI与Harness文献对照](05-RSI与Harness文献对照.md)。

```text
分析请求 → 统计证据 → 贝叶斯排序（RSIAgent 的记忆）→ 快脑小模型重排（校准概率 + 保形集合，毫秒级）
              │
              ├─ 把握够、集合只有首位、改进库没记录过错、没有条件规则拦着 ──→ 快脑直接给结论
              │
              └─ 否则转慢脑（双层递归的内层）：课程 agent 出一批本案的近邻孪生题，1/3 做探测题
                   挑战者：近邻训练（临时记忆在近邻题上学，快脑模型冻结参数读它重排）· 贝叶斯意见
                   裁决：同一批探测题上比命中，挑战者明显赢过快脑才改判；有 Key 时大模型调查员再核查
              ↓
         收据（路由、原因、校准概率、保形集合、各挑战者的探测命中、裁决）
              ↓
         外层反思 → 改进经验库（哪个组件在什么条件下有效；Beta 账本，追责与停用）
              ↓
         夜间检查（全部事件触发）：RSI-Opt 训练策略进化 → 快脑训练窗口（A-RSI）→ RRSI 进化基础 harness
```

**快脑小模型**（`app/fastbrain/`）

| 部分 | 做法 |
|---|---|
| 输入特征 | 每个候选根因 19 个：贝叶斯 5 个证据因子（取对数）+ 贝叶斯没用上的结构信号（未达显著的机台信号 × 机台热点记忆、变点是否就在本工序、PM 后突变是否在本工序机台、FDC 偏移落在哪个参数、显著共性的类型是否与根因类型吻合……）。刻意不用会泄露答案的仿真伪迹（未达显著的物料批次信号、未达 2σ 的 FDC 参数名、晶圆图特征） |
| 原始信号特征 | 每个候选再加 8 个，来自统计内核对批次原始数据的连续指标检验（`fab/analytics.raw_signals`）：先找整体变点，再在变点之后的时间窗里按工序逐台机台做 Welch t 检验（连续良率 / 失效率，不二值化），取本工序最差机台的 t 值、它领先第二差机台多少、变点前是否本来就差、变点前 72 小时内是否刚做过 PM，以及别的工序和全案的最强信号、整体变点强度。只用每道工序都有的机台因子，不用物料批次（孪生伪迹）。离线对照（同一 480 题测试集）：原特征 81.3% → 加原始信号 92.1%，困难题 71.2% → 88.8%，对数损失 0.49 → 0.23 |
| 网络 | Wide & Deep & Cross 排序网络（Wide & Deep，Google 2016；DCN-v2，Google 2021）：宽部分初始化为贝叶斯证据权重，深部分一层隐层，交叉部分是低秩 DCN-v2 交叉层，再加根因 ID 嵌入和根因偏置层；列表式 softmax 交叉熵；温度缩放校准。纯 Python，默认结构约 790 个参数 |
| 和贝叶斯的关系 | 未训练时完全等于贝叶斯排序；训练学的是“在贝叶斯之上的校正”。通过晋升门之后才拿到快脑的裁决权，否则快脑退回贝叶斯 |
| 训练数据 | 课程 agent 按固定配额出题（每症状 300 道），标签由孪生程序给出；加上工程师确认的收据（最近 20% 留作产线时间留出，不进训练） |
| 训练窗口（A-RSI） | 事件触发：没有窗口 / 新增 ≥ 20 条确认 / 产线变更 / 样本池饱和 / 慢脑推翻快脑 ≥ 8 次 / 产线命中率比留出集低 10 个百分点。从上一版继续训练，锚定上一版防遗忘 |
| RSI-Opt 内层 | 每个 epoch 末控制器决定：继续 / 学习率减半 / 回滚到最好的一轮 / 提前停止 |
| RSI-Opt 外层 | 跨 run 进化训练策略（学习率、轮数、隐层宽度、嵌入维度、正则、出题配比、产线样本权重；DCN-v2 交叉层的秩默认 4，属于“必要时才改”的旋钮，只有对数损失显著下降才接受改动）；存档、父代采样、search 训练 → select 验收 → report 确认；连续 2 个窗口失败才跑 |
| 训练知识库 | 事实（训练池里各症状的首位根因、模型偏弱的分组）与做法（控制器规则、出题配比的效果），失败追责，停用留档；被推翻的事实会让该症状下个窗口配额加倍 |

**三层三套门（名字不混用）**

| 层 | 门 | 做法 |
|---|---|---|
| RSIAgent（记忆与证据权重） | 验收门 | 见 2.4：240 题面板、配对 bootstrap、分组护栏、每采纳一次换一块面板 |
| 快脑模型训练 | 健康门 | 参数有限且不爆炸、验证损失确实下降、参数确实变了、输出不塌缩、不过拟合（验证 − 训练 ≤ 0.15）、温度在 0.5~2.0、没有哪个症状比贝叶斯差 0.25 以上；不过就换种子重试一次，再不过就停 |
| 快脑模型训练 | 晋升门 | 每晋升一次换一块全新的留出集；对数损失配对区间上界 ≤ 0、命中率下界 ≥ −2 个百分点、ECE 不变差、对贝叶斯不退步、分症状护栏 0.2、保形覆盖 ≥ 87%、产线时间留出不比在用版本和贝叶斯差 5 个百分点以上 |
| harness 配置（RRSI） | 选择门 + 上线门 + 观察期 | 选择门：白名单与防泄漏审查 → search 初筛 → select 验收（Bonferroni 校正、噪声带内只接受更便宜或更简单的）；上线门：每次全新的 report 题 + 产线回放；观察期：错误率 Wilson 区间下界高于上一版和路由承诺时回滚 |

**慢脑的两个挑战者**

| 挑战者 | 改的是什么 | 修哪种错 | 标签 | 成本 |
|---|---|---|---|---|
| 近邻训练 | 一份临时贝叶斯记忆：该症状旧份额先降权，再由执行 agent 作答、验证 agent 判定，学份额和机台热点（RSIAgent 的方式）；快脑模型参数冻结，读入临时记忆重新算特征、重新排序；用完即弃 | 产线变了，记忆里的“哪个根因常见”“根因多发在哪台机台”过时了 | 验证 agent 看干预反馈 | 高 |
| 贝叶斯意见 | 不训练，结构完全不同 | 模型自己在少见证据组合上外推出错 | 不需要 | 零 |

v0.7 早期还有第三个挑战者“只调快脑模型的根因偏置层”。演示历史 48 次慢脑里它只赢过快脑 1 次，孪生压力题上（144 道探测题）还比快脑少答对 11 道；和近邻练习叠加时会把同一个变化算两次（126 → 106）。所以把它并进近邻训练，并去掉偏置调整：练的是记忆，模型读记忆。

**RRSI 进化的是基础 harness**（`app/harness/policy.py`、`evolve.py`）：路由门槛、抽查间隔、近邻训练的开关、题量与旧份额保留比例、改判门槛、是否按改进库调整、大模型调查员何时调用，以及**条件规则**（例如“若［套刻漂移 · 证据模糊］→ 近邻训练关”）。规则只能从改进经验库提议，只能以可观察的条件字段为条件，要过防泄漏审查；正则化 = 改动预算退火 3 → 2 → 1 + 复杂度感知 + 剪枝。何时跑也是事件触发：改进库新出现 ≥ 3 条稳定或停用的经验 / 产线确认的快脑错误 ≥ 3 次且 ≥ 15% / 新快脑模型上线 / 产线变更 / 慢脑赢过快脑的比例跌到两次前的 85% 以下；连续两次没接受任何候选就退避。

**更新时机一览**

| 对象 | 何时更新 | 门 |
|---|---|---|
| 根因先验 / 机台热点 / TTSE 条目 | 每次关案；RSI 会话 | 只在验证 agent 判定或工程师确认之后写入 |
| 证据权重 | 关案、RSI 每波、夜间 | 验收门 |
| 快脑小模型 | 训练窗口的触发条件满足时 | 健康门 + 晋升门 |
| 训练策略 | 还没有策略 / 连续 2 个训练窗口失败 | select 验收 + report 确认 |
| 改进经验库 | 每次慢脑（孪生探测）、每次关案（现场结果） | Beta 阈值；推翻关案时撤回 |
| harness 配置 | RRSI 的触发条件满足时 | 选择门 + 上线门 + 观察期 |

**结果（演示数据）**：各训练窗口的快脑候选模型（加原始信号）在 480 题测试集上 91.0%–92.5%，同期贝叶斯 66.9%–75.2%；孪生 report 题上快脑接手 75%、零错误；产线刚变更的压力场景，快脑模型自己就到 92.5（贝叶斯 57.5），慢脑不再有额外收益。RRSI 因此在 2026-01 关掉了近邻训练以省孪生算力（命中率在噪声带内，上线门通过）。

**答案可靠性**：报告给出首位根因的校准概率（快脑模型温度缩放后的概率）和“覆盖真因 90%”的根因集合（分割保形，阈值来自孪生校准集）；集合不止一个根因、或结论对单一证据族敏感时，标为“需现场鉴别”；只有快脑接手且集合只有首位时才标“可直接执行”。

## 3. 可进化记忆

| 类型 | 内容 | 写入时机 |
|---|---|---|
| 环境知识 · 根因份额 | 每个症状下各根因的 Dirichlet α，初始为“教科书先验 × 4” | 产线确认 +1.0；孪生验证通过 +0.5；整改被否定 −0.5×权重 |
| 环境知识 · 机台热点 | 根因 ↔ 机台出现次数，排序时作为 P(机台 \| 根因) 的相对似然（Laplace 平滑） | 证据中与根因同工序、显著的机台 |
| 证据权重（v0.4） | 先验、共性分析、FDC、PM 时序、机台热点 5 类证据的可信度指数；每版记录样本数、来源与验收门结果 | 孪生练习每波 / 产线关案 / 夜间重拟合，通过验收门才采纳 |
| 可复用流程（TTSE 做法轨） | “条件［症状；共性显著与否；富集在机台/批次；是否 PM 后］→ 优先排查 X；有效的预防措施” | 验证通过 +1；按它先试却失败 −1 并追责 |
| 失败教训（TTSE 做法轨） | “条件［…］下按 X 整改未能恢复指标” | 再次失败即再次印证；同条件下 X 验证有效则被推翻一次 |
| 机台事实（TTSE 事实轨） | “机台 T 与根因 X 相关（验证 agent 确认）” | 验证通过；满 3 次确认才生效；按它整改却没恢复时追责 |
| 课程做法（TTSE 做法轨） | “某症状练习失败后针对性加练” | 加练题是否通过验证；停用后课程 agent 不再对该症状加练 |

**TTSE 双轨用在三个 agent 上**（v0.7）：TTSE（arXiv:2609.24289）是不改参数、在测试时靠经验进化的 agent 框架，正好对应 RSIAgent 的三个 agent。执行 agent 作答时检索“稳定”的做法条目（同条件下 P ≥ 0.8、排在前三、后验不低于首位一半，且比首位自己的条目更可靠才先试它）；课程 agent 读自己的加练条目；验证 agent 是唯一的裁判。失败追责到当时实际用到的条目；P < 0.45 且失败 ≥ 4 次停用，停用的条目留档可查、不再被检索；拿不准时一律记为做法，不升格为事实。

真实环境和孪生共用同一套合并逻辑（`app/rsi/memory.py`、`app/rsi/calibration.py`），区别只在权重与来源标记。所有变化都写入学习事件，带来源（产线/孪生）和来源案例/练习题。

## 4. 分析工作流（DBOS）

受理 → 取数与统计证据 → 根因排序（同时用教科书先验再排一次，得到“若不学习”的反事实；不确定时计算各鉴别验证的预期信息增益）→ 调取记忆 → [代码模式调查] → 5-Why → CAPA → 评审（隔离：只看证据与措施）→ 落库。

我实际做过崩溃测试：在分析中途对进程执行 `os._exit` 强杀，重启后 DBOS 自动恢复，工作流完成，结果只落库一次。

## 5. 控制台与协议选型

### 5.1 控制台布局：参考 Claude / Codex（v0.5）

```text
┌─ 左侧栏 ─────────────┬──────────────────── 主区域 ────────────────────────┐
│ K Kaizen        [⊟] │ 默认：对话                                          │
│ ✎ 新对话             │   空对话：问候 + 待关注事项 + 输入框 + 示例问题        │
│ ── 功能 ──           │   消息：思考过程（折叠）+ 回答 + 卡片（打开 KZ-0121 →）│
│ 质量总览             │        + 关案批准卡片                                │
│ 案例库               │   输入框（模式：根因分析 / 改进教练 / 自我进化）        │
│ CAPA 看板            │                                                     │
│ 自我进化             │ 点左侧功能或消息里的卡片 → 在同一主区域完整显示该页面；   │
│ 改进周期             │ 顶部“← 返回对话”或点任一条最近对话回到对话。             │
│ 审计日志             │                                                     │
│ ── 最近对话 ──       │                                                     │
│ 分析 KZ-0121    [×] │                                                     │
└─────────────────────┴─────────────────────────────────────────────────────┘
```

- 不再有右侧面板，也不会自动跳转：agent 只在消息里放卡片，用户点开才切换到页面。主区域要么是对话，要么是一个完整页面。
- 多条对话保存在本机浏览器（localStorage，最多 40 条），侧栏可切换、删除；有待批准关案的对话前面有橙点。
- 侧栏可收起；手机宽度下侧栏变成抽屉，左上角按钮打开。

| 需要 | AG-UI 1.0 事件 | 做法 |
|---|---|---|
| agent 推荐打开页面 | `ACTIVITY_SNAPSHOT`（`activityType = kaizen.case / kaizen.learning / kaizen.rsi / kaizen.cycle / kaizen.overview`） | 在消息里留一张卡片（前三名根因、学到了什么、自我进化进度），卡片上的“打开 … →”跳到 `content.route`。`content.open = true` 只表示推荐打开（按钮突出显示），界面不会自动切走对话。页面数据由界面按路由自己拉取，不回传给大模型 |
| 实时进度 | `ACTIVITY_DELTA`（JSON Patch） | 自我进化会话的阶段、已练题数、命中率变化；对话里的卡片同时画出实时曲线和最近 5 条事件 |
| 共享上下文 | `STATE_SNAPSHOT` / `RunAgentInput.state` | `workspace.focusCaseId`、`workspace.openPage`：用户正在看哪个案例、哪个页面，agent 知道 |
| 关案（改写产线记忆） | `RUN_FINISHED(outcome = interrupt)` + 下一次运行的 `resume` | 识别到“确认 KZ-xxxx 根因是 …”时不直接关案，而是请求批准；批准（可附备注）后带 `resume: [{status: "resolved", payload: {approved: true}}]` 发起下一次运行才执行；取消则什么都不写。待批准期间输入框锁定 |
| 思考过程、阶段 | `REASONING_*`（默认折叠）、`STEP_*` | 分析工作流步骤、自我进化三阶段 |

页面只渲染自有组件目录，不渲染大模型生成的 HTML。

“自我进化”页面分三页，每页顶部有一句说明（v0.5 起“记忆条目”不再单独展示，只在内部使用）：

| 分页 | 回答的问题 | 内容 |
|---|---|---|
| 概览 | 自我进化有没有用？ | 冷启动命中率、最近一次会话的前后对比、真实案例持续学习 vs 冻结先验、证据权重、消融对比、两种学习写入同一套记忆的示意图 |
| RSI 学习 | 智能体在孪生里练了什么？ | 三个角色说明、实时直播、会话时间线（每次会话前同步了哪些产线变更、命中率前后、持平原因）、证据权重重拟合与验收门记录、练习题明细、知识缺口与信息价值 |
| 持续学习 | 从产线真实案例学到了什么？ | 预序回放学习曲线、根因先验（教科书 → 当前）、机台热点、学习时间线 |

## 7. 安全与合规

- 密钥只来自环境变量；写接口、`/agui`、`/mcp` 都要求 Bearer Token；
- 对 MES/YMS/FDC 只读，对 OT 控制系统零写入；
- 学习只发生在验证之后（产线确认 / CAPA 验证 / 孪生验证 agent 判定），全部可追溯，记忆可人工停用；
- 证据权重每次更新都要过验收门；在控制台里关案要人工批准（AG-UI 中断），批准人与备注进入审计；
- 孪生经验权重低于产线确认；在线模式下孪生校准题不改动产线先验；
- 对应《智能体规范应用与创新发展实施意见》（2026-05）：可追溯、可问责、权限管理、人在回路。
