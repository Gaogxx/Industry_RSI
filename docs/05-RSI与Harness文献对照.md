# RSI 与 Harness 文献对照：Kaizen 的每个做法为什么重要、怎么做

本文把 Kaizen 已有的做法和 v0.6 新增的 Harness 层，逐条对应到 2025–2026 年的论文与技术报告：文献怎么说、为什么重要、Kaizen 具体怎么做。
数字均取自论文正文或摘要（2026-11 核对）；标注“媒体”的数字只出现在媒体报道里，一手来源没有找到。

## 1. 已有做法的文献依据

### 1.1 验收门：每次更新都要在封存的题上“不退步”

- **文献**
  - OpsHarness：去掉验收门的自进化版本比不进化还差。
  - RSI-Opt 刻意不设验收门，结果在训练任务上一路上涨（+10.48 → +14.33），留出任务却在第 1 代之后不再提升。强模型在留出任务上甚至变差（Opus：+5.22 → +4.87）。
  - RRSI 用“稳定性下限”：候选不能比当前最好低于噪声带。
- **为什么重要**：自进化最常见的失败不是学不会，而是学到噪声、越改越窄。
- **Kaizen 怎么做**
  - 证据权重每次重拟合都过验收门（面板对数损失不变差、首位命中率最多降 1 个点）。
  - v0.6 起，harness 策略晋升要过 search / select / report 三道题集。
  - 可靠度模型晋升要过留出集上的配对 bootstrap 区间。

### 1.2 数字孪生 = 可验证的环境；标签从不来自模型自评

- **文献**
  - 五大路线综述把评估信号按强度排序：形式化验证器最强，模型自评最弱；实际提升的大小也按这个顺序排列。
  - R-Zero 用多数投票做伪标签，伪标签准确率从 79% 掉到 63%，几轮后崩溃。
  - Self-Rewarding 没有真值，作者自己承认 reward hacking 是开放问题。
  - A-RSI 的答案由程序计算；1,000 道抽检题与独立求解器 1000/1000 一致。
  - Voyager 去掉“验证后才入库”，发现的物品少 73%。
- **为什么重要**：自我改进的上限取决于判对错的信号有多可靠。
- **Kaizen 怎么做**
  - 验证 agent 只看孪生的干预反馈：按提议整改后良率是否恢复，看不到执行 agent 的推理。
  - 产线标签只来自工程师关案。
  - 孪生标签权重 0.5，产线确认权重 1.0。
  - v0.6 的近邻练习、可靠度模型训练也只用这两种标签。

### 1.3 贝叶斯记忆与带条件的经验条目

- **文献**
  - TTSE 把经验写成“在 <条件> 下：<做法>”。
  - Bayesian-Agent 把每条经验当成假设，用 Beta 后验管理；默认 P < 0.45 且失败 ≥ 4 次停用，P ≥ 0.72 且 ≥ 3 次标为稳定。
  - ACE 的经验手册是带编号的条目加有用 / 有害计数，只做增量修改；它指出整段重写会导致“上下文坍塌”。
  - A-MEM 直接覆盖旧笔记、没有版本，审计上不可取。
- **为什么重要**：经验要能被验证、被推翻，还能说清楚在什么条件下有效。
- **Kaizen 怎么做**
  - 根因先验是 Dirichlet 计数。
  - 流程与教训条目保留条件和通过 / 失败次数，失败多于成功 2 次自动停用。
  - v0.6 的任务经验沿用 Bayesian-Agent 的阈值。
  - 所有更新都是增量修改，停用的条目留档。

### 1.4 课程 agent：按信息价值出题

- **文献**
  - Voyager 把课程换成随机出题，发现的物品少 93%。
  - R-Zero 的出题目标是让解题方成功率接近 50%（奖励 1 − 2|p̂ − ½|）。
  - **反例**：A-RSI 发现按固定配额随机抽题，比失败优先、难度阶梯都好（−0.82 到 −2.63 分）。原因是随机池保留了“写不完”的题，而这类题的终止奖励信号最强。
- **为什么重要**：出题决定了练什么，但“难题优先”并不总是对的。
- **Kaizen 怎么做**
  - 课程 agent 用知识梯度 × 证据模糊率估算“再练几道能涨多少”。
  - 校准批按信息价值分配症状，难度混合（易 : 中 : 难 = 2 : 4 : 4），不全选难题。
  - v0.6 的近邻练习是同一个课程 agent 针对单个案例出题。

### 1.5 产线变更与部分遗忘

- **文献**
  - TTSE 的出发点就是：环境一变（文件位置、数据格式、模板），旧经验就失效；失败后要能分清是做法错了还是对环境的认识错了。
  - SEAL 连续自编辑时出现灾难性遗忘，作者没有优化保留。
- **为什么重要**：工厂会换供应商、导入新机台。记忆跟不上，越有把握反而越容易错。
- **Kaizen 怎么做**
  - 产线变更同步到孪生时，受影响症状学到的份额只保留 20%。
  - 下一次 RSI 会话把这些症状的校准题比例提高到 4 倍，并允许它们更新先验。
  - 真实案例回放用同样的规则。

### 1.6 三套题集互不重叠

- **文献**
  - RSI-Opt 用种子 100/101 搜索，102/103 选择，200–202 报告。
  - Agnes 的 Train / Eval / Sealed 三份数据中，Sealed 对所有提议者不可见。
- **Kaizen 怎么做**
  - 测试集、验收门面板、练习题的种子段互不重叠。
  - v0.6 的 RRSI 进化用 search / select / report 三套孪生题，report 只在最后用一次。

## 2. v0.6 新增：Harness 层

### 2.1 快慢双脑（Agnes Harness）

- **文献**
  - Agnes 把决策模型当“小脑”（System 1），大模型当“大脑”（System 2）。
  - 必须交给大模型的情形：每个任务第一步、上一步失败、正在检查设备、决策模型已连续执行 3 步。
  - 置信度低于阈值时交还，并附上决策模型的概率分布。
  - 报告数字（封闭仿真）：单步 0.53 s 对 7.6 s；单次决策 $0.000091 对 $0.00247。
- **为什么重要**：大部分案例证据清楚，不需要深度核查；把算力留给真正难、真正新的案例。
- **Kaizen 怎么做**
  - **快脑**：统计内核 + 记忆，毫秒级给结论，不跑孪生，也不调大模型。
  - **必须转慢脑的情形**：缺数据、S1、该产线该症状还没有现场确认过的先例、经验库记录快脑在同条件下答错过、同症状连续快脑后的周期抽查、可靠度低于阈值、保形集合不止一个根因。
  - **结果**
    - 演示历史：快脑接手的 28 个案例全部被现场确认正确（95% 区间 88%–100%）。
    - 孪生 report 题：快脑接手 44%，没有答错；只用快脑时会错 14 道。

### 2.2 测试时训练（TTT）与课程 agent 互补

- **文献**：Agnes Sys1 报告的 TTT 设计如下，但报告明说是方案，没有实验结果。
  - 逐请求出可验证的辅助题，只更新末端 RMSNorm 的缩放参数，并对基线做 KL 锚定。
  - 预测完即丢弃；样本不可靠或结果变差就回退。
  - 方法引用 Sun et al., ICML 2020。
- **为什么和课程 agent 互补**：课程 agent 决定长期该练什么，面向所有症状的知识缺口；TTT 只为眼前这一案服务。两者用同一个出题器（`Curriculum.test_time`）。
- **Kaizen 怎么做**
  - 慢脑里，课程 agent 针对本案出 36 道孪生近邻题，其中 12 道留作探测。
  - 先把临时记忆里该症状的旧份额降到 10%，再用练习结果学习；证据权重以线上版本为中心强锚定。
  - 探测题练习前后各答一次（每题一次机会），至少多答对 2 道才采纳练习后的结论。
  - 用完即弃，留下的是经验。
- **结果**
  - 产线刚变更、记忆还没跟上的压力场景：只用快脑 57.5% → 快慢双脑 77.5%，配对差 95% 区间 [+2.5, +37.5] 个百分点。
  - 平常场景基本持平：−1.0 个点，区间 [−4.2, 0]。

### 2.3 双层递归（Harness²）

- **文献**
  - **内层（任务级）**：提议通用和领域两类候选 → 在同一任务上探测、做行为对比 → 合成有证据支持的改动。
  - **外层（改进级）**：反思模块把“什么条件下哪种改动修好了什么”写进经验库；只有执行对比支持的经验才入库；下一个任务仍从干净的基础流程出发。
  - **结果**：GLM-5 在 WorkBuddy-Bench 上 64.2 → 75.7（单步）。去掉经验库后 WorkBuddy / JobBench 分别降 3.1 / 1.8 分。
  - **局限**：没有正确性信号，只能靠行为对比；附录列了 9 个退步案例。
- **Kaizen 怎么做**
  - **内层**：通用候选 = 近邻练习；领域候选 = 证据族对照。
    - 探测比 Harness² 更强：孪生近邻题有真值。
    - 合成规则：探测证明有效才改结论；对单一证据族敏感的结论标为“需现场鉴别”。
  - **外层**分两次反思：
    - 内层做完立刻按孪生探测结果更新“近邻练习”经验；
    - 关案后按现场结果更新“快脑可信”经验和“机台 ↔ 根因”事实。
  - 某条件下近邻练习反复无效（经验已停用），下次提议直接跳过，省下孪生算力。

### 2.4 双轨任务经验（TTSE）

- **文献**
  - TTSE 在 ALFWorld 上达到 98.51%（GLM-5）；GDPevo 上双轨 0.2616，只用 TIP 0.2380，只用 FACT 0.1918。
  - **局限**：规则没有留出集验证，归咎也可能错。
- **Kaizen 怎么做**
  - **事实轨**：只记现场确认过的“机台 ↔ 根因”，满 3 次独立确认才生效，之前是候选。
  - **做法轨**：“在 <条件> 下快脑可以直接给结论”“在 <条件> 下先做近邻练习”。
  - 答错的结论会被追责，P < 0.45 且失败 ≥ 4 次停用，留档可审计。
  - 关案标签被推翻时，撤回这次带来的经验计数（Agnes：标签被推翻自动撤销）。
  - Kaizen 补上了 TTSE 缺的验证：经验只来自孪生探测和现场确认。

### 2.5 RRSI 与跨 run 进化

- **文献**
  - **RRSI 提议端**：每个候选能捆绑的改动数退火；记录每次改动的组件、假设、实测效果；停滞时尝试没改过的组件。
  - **RRSI 选择端**：拒绝夹带基准专属信息的改动；稳定性下限；改进在噪声带内只有降低成本才接受；剪掉长期无贡献的组件。
  - **RRSI 结果**：进化集最多 +6.0，5 个分布外基准最多 +4.3，policy token 少 30%。
  - **RSI-Opt 与 DGM**：策略存档跨 run 继承，父代采样 ∝ sigmoid(得分 − 中位数) / (1 + 子代数)。
  - **Agnes**：字典序目标——先保证通过数不降、安全失败零增加，再看速度和成本；上线观察期内错误率显著上升就自动回滚。
- **Kaizen 怎么做**
  - **可进化的旋钮（白名单，带上下限）**：快脑可靠度门槛、强制抽查间隔、近邻练习题量、旧份额保留比例、练习权重、采纳门槛、是否按经验库调整。
  - **存档**：每个候选都留档，包括被拒的。
  - **评估题**：三套孪生题互不重叠，各含两种不同症状的产线变更压力题，防止进化只适应平常场景、一味压缩近邻练习。
  - **验收顺序**：
    1. 快脑答错数增加，直接拒绝；
    2. 命中率配对差的 95% 区间下界 > 0，接受；
    3. 下界 ≥ −2 个点且孪生练习题数减少 10% 以上，接受；
    4. 其余拒绝。
  - **上线**：最终用 report 集决定是否上线，上线后进入观察期：该版本下已确认的快脑结论里答错 ≥ 3 次且 ≥ 20%，自动回滚。
  - **演示存档**：2026-06 和今天两次运行共 10 个候选，全部被拒：8 个改进在噪声带内又不省算力，2 个区间下界低于 −2 个百分点。

### 2.6 训练机制：能和 RSIAgent 并存吗？训练什么？何时更新？

- **文献**
  - **A-RSI**：只训练求解模型（GRPO），标签由程序计算。
    - 换池规则：同一池至少 3 个窗口，且有学习信号的题数跌到 2 个窗口前的 85% 以下，或正确率比 2 个窗口前高 10 个点以上。
    - 健康门不过重试一次，再不过就停，回到上一个被接受的检查点。
    - 局限：没有留出集晋升门，没有置信度校准、拒答和不确定性估计。模型预测自己会错哪些题，AUC 约 0.50。
  - **"Harness Evolution Hits a Ceiling"**：harness 还没进化到头时先进化 harness；等主要失败变成内容错误，再训练权重。
- **结论**：可以并存。RSIAgent 继续负责不训练的那部分（记忆、先验、证据权重）。训练机制训练的是一个 9 参数的可靠度模型（逻辑回归），不是大模型。
  - **输入**：快脑排序的特征。
  - **输出**：首位根因是真因的概率。
  - **作用**：决定快慢路由和报告里的置信说明，不改根因排序。
- **何时更新**（任一满足即开训练窗口）：
  - 新增 20 条现场确认；
  - 孪生同步了产线变更；
  - 样本池信息量跌到 2 个窗口前的 85% 以下（同一池至少 3 个窗口），此时换一批孪生题。
- **晋升**
  - 健康门：损失有限、样本 ≥ 200、参数确实变了。
  - 留出集上对数损失的配对 bootstrap 95% 区间上界 ≤ 0，且 ECE 不变差。
  - 演示历史里前 4 个窗口都没晋升，今天的窗口晋升，ECE 0.088。
- **答案可靠性**：在孪生校准集上定保形阈值，给出覆盖真因 90% 的根因集合；留出集实测覆盖 95%。
  - 集合里不止一个根因时，报告明确标为“需现场鉴别”。
  - 这个覆盖率只对孪生分布严格成立；产线上用已确认的收据持续监控（演示历史覆盖 99%）。
- **大模型权重**：暂不训练，只留接口。大模型在 Kaizen 是可选的，训练链路不能成为离线模式的依赖。

## 3. 五大路线在 Kaizen 的取舍

| 路线 | 代表工作 | Kaizen 的结论 |
|---|---|---|
| ① 模型权重训练 | Self-Rewarding、SPIN、Quiet-STaR、SEAL | 根因判断链路没有神经网络权重可训。借鉴两点：SPIN 的固定真值锚点（工程师确认的根因永久保留）；SEAL 的“更新后的表现即奖励”，Kaizen 的验收门就是这样做的 |
| ② 提示与框架进化 | STOP、ADAS、TextGrad、DSPy | 只影响可选的大模型层。借鉴：TextGrad 的验证集准入；ADAS 用多次运行加 bootstrap 区间做决定 |
| ③ 记忆与技能库 | Voyager、Reflexion、ACE、MemEvolve | **最适合**，就是 Kaizen 的主线：条件化条目、增量合并、验证后入库；MemEvolve 式的记忆超参数搜索对应 v0.6 的 RRSI 策略进化 |
| ④ 自改代码 | Gödel Agent、DGM、AlphaEvolve、ShinkaEvolve | 产线运行时不让 agent 改自己的代码（变更管控）。借鉴存档、父代采样、先便宜后贵的分级评估 |
| ⑤ 多智能体协同进化 | R-Zero、EvoAgentX、AI Scientist | 借鉴 R-Zero 的出题目标（成功率约 50%）和它的教训：永远不把自己的高置信结论当标签 |

## 4. 已知局限

- 所有数字都来自模拟数据与数字孪生。孪生没有用本厂数据校准之前，学到的是孪生而不是产线。
- 近邻练习在平常场景基本持平（−1.0，区间 [−4.2, 0]），它的价值集中在产线变更之后、RSI 会话之前。
- RRSI 进化在演示数据上多数候选被拒。这是严格验收门的预期行为（RRSI 原文 30 轮中 10 轮被接受）。
- 首次生成演示数据比 v0.5 慢，因为每个历史案例都要走快慢双脑。服务器仍然 2 秒内可用，数据在后台生成。
